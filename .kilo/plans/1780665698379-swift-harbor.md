# GitHub Actions 部署到服务器方案

## 概述

在 push 到 `master` 分支时自动编译 Linux amd64 二进制文件，通过 SSH 部署到你的服务器并重启服务。

## 新增文件

### `.github/workflows/deploy.yml`

新增一个部署 workflow，内容如下：

```yaml
name: Deploy to Server

on:
  push:
    branches: [master]
    paths-ignore:
      - 'docs/**'
      - '*.md'
      - '.gitignore'

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Go
        uses: actions/setup-go@v5
        with:
          go-version: '1.26'

      - name: Build for Linux amd64
        run: make build-linux-amd64

      - name: Copy binary to server
        uses: appleboy/scp-action@v0.1.7
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SSH_PRIVATE_KEY }}
          port: ${{ secrets.SERVER_PORT || '22' }}
          source: 'build/linux_amd64/fast-note-sync-service'
          target: '${{ secrets.SERVER_DEPLOY_PATH }}'
          strip_components: 2
          rm: false

      - name: Restart service
        uses: appleboy/ssh-action@v1.2.0
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SSH_PRIVATE_KEY }}
          port: ${{ secrets.SERVER_PORT || '22' }}
          script: |
            sudo systemctl stop ${{ secrets.SERVER_SERVICE_NAME || 'fast-note' }}
            sudo chmod +x ${{ secrets.SERVER_DEPLOY_PATH }}/fast-note-sync-service
            sudo chown -R $(whoami):$(whoami) ${{ secrets.SERVER_DEPLOY_PATH }} 2>/dev/null || true
            sudo systemctl start ${{ secrets.SERVER_SERVICE_NAME || 'fast-note' }}
            sleep 3
            sudo systemctl status ${{ secrets.SERVER_SERVICE_NAME || 'fast-note' }} --no-pager

      - name: Health check
        uses: appleboy/ssh-action@v1.2.0
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SSH_PRIVATE_KEY }}
          port: ${{ secrets.SERVER_PORT || '22' }}
          script: |
            curl -sf http://localhost:9000/api/v1/health 2>/dev/null || curl -sf http://127.0.0.1:9000/health 2>/dev/null || echo "Health check endpoint not found, but service may still be starting."
```

## 用户需要在 GitHub 仓库配置的 Secrets

| Secret 名称 | 说明 |
|---|---|
| `SERVER_HOST` | 服务器 IP 或域名 |
| `SERVER_USER` | SSH 用户名（如 `root` 或部署用户） |
| `SSH_PRIVATE_KEY` | SSH 私钥（对应服务器的公钥） |
| `SERVER_PORT` | SSH 端口，可选，默认 22 |
| `SERVER_DEPLOY_PATH` | 部署路径，默认 `/opt/fast-note` |
| `SERVER_SERVICE_NAME` | systemd 服务名，可选，默认 `fast-note` |

## 部署流程说明

1. **构建** - 复用项目已有的 `make build-linux-amd64` 编译 CGO_ENABLED=0 的纯 Go 二进制
2. **上传** - 使用 `appleboy/scp-action` 将二进制传到服务器的 `/opt/fast-note/` 目录
3. **重启** - 通过 SSH 执行 `systemctl stop/start` 重启 `fast-note` 服务
4. **健康检查** - 验证服务是否正常启动

## 服务器端前置条件

服务器需要提前准备好：
- systemd 服务已配置（安装脚本已自动完成）
- SSH 公钥已添加到服务器的 `~/.ssh/authorized_keys`
- 部署用户有 `sudo systemctl` 权限（可在 sudoers 中免密码配置）

## 扩展考虑（可选）

- **通知**: 可在 deploy 成功后加 `actions/checkout` 的失败通知（飞书/钉钉/Slack Webhook）
- **回滚**: deploy 前备份旧二进制，失败时自动恢复
- **仅构建不走全流程**: 可加 `workflow_dispatch` 触发以手动选择部署或不部署
